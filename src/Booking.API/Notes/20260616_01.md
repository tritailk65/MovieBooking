Mình xem Booking service hiện tại rồi. Nó đang có 2 endpoint trong [BookingApi.cs](/Users/tari/Project/Microservice_Learning/MovieBooking/Booking.API/Apis/BookingApi.cs:15):

```http
POST /api/booking/
POST /api/booking/draft
```

Hiện tại `draft` dùng để tính preview/tổng tiền từ danh sách ghế, còn `/` tạo booking trực tiếp từ `seatItems`. Nhưng sau khi Seat Service đã có `ValidationReservation` và `ConfirmReservation`, Booking Service nên chuyển trọng tâm sang **booking từ reservationId**, không còn tin trực tiếp danh sách ghế client gửi lên nữa.

**MVP Flow Nên Có**
Cho MVP đầu tiên, mình đề xuất Booking Service cần các endpoint này:

```http
POST /api/booking/draft
```

Giữ endpoint này. Dùng để preview đơn hàng trước khi tạo booking. Nhưng về sau data nên lấy từ Seat validation hơn là client tự gửi seat/basePrice.

```http
POST /api/booking/from-reservation
```

Endpoint quan trọng nhất cần thêm.

Input:

```json
{
  "userId": "u1",
  "showtimeId": 10,
  "reservationId": "..."
}
```

Flow:

```text
Booking Service gọi Seat Service validation-reservation
Nếu hợp lệ:
  tạo Booking
  add BookingItems từ SeatReservation.SeatIds
  lưu reservationId vào Booking
  status: SeatConfirmed hoặc PendingPayment nếu bạn thêm status mới
  trả bookingId + total + remainingSeconds
Nếu không hợp lệ:
  trả 409
```

Đây là endpoint “bắt đầu checkout thật”.

```http
GET /api/booking/{bookingId}
```

Cần có để frontend lấy lại trạng thái booking sau refresh/reload, hoặc khi user quay lại trang thanh toán.

Response nên có:

```json
{
  "bookingId": 123,
  "userId": "u1",
  "showtimeId": 10,
  "reservationId": "...",
  "status": "seatconfirmed",
  "items": [],
  "total": 180000
}
```

```http
GET /api/booking/users/{userId}
```

Không bắt buộc ngay, nhưng rất nên có cho “vé/đơn của tôi”. MVP đặt vé thường cần màn lịch sử đặt vé.

```http
POST /api/booking/{bookingId}/payment-success
```

Vì bạn chưa có Payment Service thật, MVP nên có endpoint giả lập payment success.

Flow:

```text
Load booking
Check booking còn ở trạng thái chờ thanh toán
Gọi Seat Service confirm-reservation
Nếu confirm OK:
  booking.SetPaidStatus()
  save
  trả success
Nếu confirm fail:
  booking.SetCancelledStatus() hoặc PaymentFailed
  trả conflict
```

Sau này endpoint này sẽ được thay bằng handler của `PaymentSucceededIntegrationEvent`.

```http
POST /api/booking/{bookingId}/payment-failed
```

Hoặc:

```http
POST /api/booking/{bookingId}/cancel
```

Flow:

```text
Load booking
Gọi Seat Service release-reservation
booking.SetCancelledStatus()
save
```

MVP có thể gộp payment failed và cancel thành một endpoint cancel trước.

**Thứ Tự Làm**
Mình sẽ làm theo thứ tự này:

1. Thêm field `ReservationId` vào Booking aggregate/table nếu chưa có.
2. Thêm client/service trong Booking API để gọi Seat Service:
   ```text
   ValidateReservation
   ConfirmReservation
   ReleaseReservation
   ```
3. Thêm `POST /api/booking/from-reservation`.
4. Thêm `GET /api/booking/{bookingId}`.
5. Thêm `POST /api/booking/{bookingId}/payment-success`.
6. Thêm `POST /api/booking/{bookingId}/cancel`.
7. Sau đó mới làm `GET /api/booking/users/{userId}`.

**Tối Thiểu Nhất Để MVP Chạy Được**
Nếu muốn ít endpoint nhất:

```http
POST /api/booking/from-reservation
GET  /api/booking/{bookingId}
POST /api/booking/{bookingId}/payment-success
POST /api/booking/{bookingId}/cancel
```

Cộng với endpoint draft hiện có là đủ cho MVP.

Điểm quan trọng: từ giờ Booking Service không nên tin `seatItems` do client gửi để tạo booking chính thức. Nó nên tin `reservationId`, rồi gọi Seat Service validate để lấy seat data hợp lệ.
